## 1. 控制方向与层次

你可以从单电机接口向上理解云台，但实际执行方向是任务调用应用，再由应用调用驱动。

```text
任务层        Control_Task：何时初始化、何时更新
输入/命令层   RemoteInput → InputState → SourceArbitration → RobotCmd
消息层        Gimbal_Command_Topic：最新目标；INS_State_Topic：最新姿态
应用层        Gimbal_Update：双轴模式、恢复、目标、控制器与反馈
算法层        Class_PID：Yaw 角度环与速度环
设备层        Class_DMMotor：许可、协议编码、反馈、ready 与基础保护
BSP 层        CAN_Tx_Perform / CAN_Tx_Submit：复制到软件发送通道
发送任务      Can_Tx_Task：每 1 ms 轮询软件通道
HAL/硬件      HAL_FDCAN_AddMessageToTxFifoQ → CAN 总线 → 电机内部控制器
```

算法不是每条路径都必须经过的独立中转：Yaw 在 Gimbal 里调用 PID；Pitch 把 MIT 增益发到电机内部。Topic 也不是逐层向下的通用总线：应用到自己拥有的电机使用直接函数调用。

## 2. 从一台电机开始

[Class_DMMotor](../../User_File/Device/Peripheral/Motor/DMmotor/dmmotor.cpp) 提供以下能力：

| 阶段 | 函数 | 实际作用 |
| --- | --- | --- |
| 初始化 | `Init(bus, can_id, master_id, mode, reverse, pmax, vmax, tmax)` | 保存参数；注册 CAN 回调、Daemon 和设备服务；不发送使能、不设置机械零位、不改变电机端模式 |
| 请求运行 | `RequestEnabled(true)` | 保存应用许可，首次/状态变化时尝试提交 Enable；成功不等于已 ready |
| 看反馈 | `GetFeedbackSnapshot()` | 一致读取位置、速度、状态及 online/requested_enabled/actual_enabled/fault/ready |
| 周期转矩 | `SetTorque(torque_nm)` | 调用 `SetMIT(0,0,0,0,torque_nm)` |
| 周期 MIT | `SetMIT(position_rad, velocity_rad_s, kp, kd, torque_nm)` | 未 ready 时全部安全化为零；限幅、方向转换、量化、打包 8 字节并 Publish |
| 请求停止 | `RequestEnabled(false)` | 首次/状态变化时覆盖安全目标并提交 Disable；失败项交低频服务补交 |

正确生命周期是 **初始化成功 → 应用按功能条件请求使能 → 新鲜反馈确认 ready → 允许有效输出**。ready 本身包含 requested_enabled，若先等 ready 再请求使能，会永远等不到。

驱动 ready 要求请求使能、反馈在线、反馈 state==1、无故障、已建立位置反馈、没有待提交的离线失能。驱动在线窗口为合法运动反馈年龄 `<100 ms`。应用可继续调用 SetMIT/SetTorque，未 ready 时由驱动保护。

这些对象须有足够长的生命周期，当前应用使用静态私有 Context。不要把 Init 放进每周期更新，不要在其他模块再次注册同一设备。

## 3. 谁创建和唤醒控制任务

启动链：

```text
main()
  → CubeMX 外设初始化
  → System_Init()
  → osKernelInitialize()
  → MX_FREERTOS_Init()
      → BSP_CAN_ConfigInit()
      → Board_CreateTasks()
          → osThreadNew(Control_Task, ...)
          → osThreadNew(Can_Tx_Task, ...)
          → osThreadNew(Status_Task, ...)
          → osThreadNew(BMI088_Task, ...)
  → osKernelStart()
```

源码：[main.c](../../Core/Src/main.c)、[freertos.c](../../Core/Src/freertos.c)、[云台板任务列表](../../User_Config/Board/board_tasks_gimbal.c)。

控制唤醒链：

```text
TIM4_IRQHandler()
  → HAL_TIM_IRQHandler(&htim4)
  → HAL_TIM_PeriodElapsedCallback(htim)
  → TIM_PeriodElapsedCallback(htim)
  → Task1ms_Callback()
  → osThreadFlagsSet(ControlTaskHandle, 0x0001)
  → Control_Task 的 osThreadFlagsWait(...) 返回
```

源码：[中断入口](../../Core/Src/stm32h7xx_it.c)、[用户回调](../../User_File/System/callback/callback.cpp)。中断只通知任务，完整云台控制在任务中执行。`TIM1msTask` 是另一个周期服务任务，承担传输维护/按键/灯效等，不是云台控制入口。

GimbalBoard 的 [Control_Task](../../User_File/Task/Control_Task_Gimbal.cpp) 启动一次执行：

```text
BoardTransport_Init()
→ RobotCmd_Init(绑定本地云台、本地发射、远端底盘输出)
→ RemoteInput_Init()
→ Gimbal_Init()
→ Shoot_Init()
```

每次 1 ms 唤醒执行：

```text
BoardTransport_Poll()
→ RemoteInput_Update()
→ RobotCmd_Update()
→ Gimbal_Update()
→ Shoot_Update()
```

ControlTask 进入后提升至 High1；BMI088 为 High2；CanTxTask 为 High；StatusTask 为 Low。它们是不同任务，顺序设计不构成 CAN 实际发送或设备执行完成的同步保证。线程标志也不是历史 tick 队列，任务拖延时不能假设逐个补算了所有控制周期。

## 4. 命令如何到达 Gimbal

| 调用者 | 函数/接口 | 数据及效果 |
| --- | --- | --- |
| Control_Task | `RemoteInput_Update()` | 从 S.BUS 完整帧快照整理输入，检查 50 ms 新鲜度、failsafe 和 200 ms 解锁条件 |
| RemoteInput | `InputState_SubmitRemote(remote)` | 写固定 Remote 状态；当前只填底盘命令 |
| RobotCmd_Update | `InputState_Read()` → `SourceArbitration_Resolve()` | 仲裁来源、Remote 安全许可、数值和新鲜度；可选视觉覆盖 |
| RobotCmd_Update | `GimbalChanged()` → `RobotCmd_SetGimbal()` | 目标/模式变化才标记 dirty；安全许可失效则装载 DISABLED |
| RobotCmd_Update | `Gimbal_Command_Output.Publish()` | 调用注入的本地 Output |
| Output | `LocalPublisher` 的绑定函数 → `Publisher::Publish()` → `Topic::Publish()` / `PublishAt()` | 覆盖数据、递增 sequence、写时间戳与 valid；不触发 Gimbal 函数 |
| 随后由 Control_Task 调用 Gimbal_Update | `Gimbal_Command_Topic.ReadWithMeta()` | 取得完整命令和序号；尚未发布时采用默认 DISABLED |

源码：[输入](../../User_File/Application/Input/remote_input.cpp)、[仲裁](../../User_File/Application/Input/source_arbitration.cpp)、[RobotCmd](../../User_File/Application/RobotCmd/RobotCmd.cpp)、[Output](../../User_File/System/MessageCenter/output.h)、[Topic](../../User_File/System/MessageCenter/topic.h)。

`GimbalCmd` 的角度是 **INS 坐标系 rad**，速度是 rad/s 前馈。云台命令按变化发布，Gimbal 读取时不检查命令年龄；失联许可由输入/RobotCmd 处理。不能单独给命令加 10 ms 超时却不改变发布策略，否则保持不动的目标也会过期。

当前 S.BUS 没有填 `remote.gimbal`，其默认是 DISABLED；VTM、Keyboard、Vision 只有提交接口，尚未绑定实际设备。仅打开云台编译开关并不会获得已接入的摇杆云台控制。

## 5. Gimbal_Update 内部一周期

源码：[Gimbal.cpp](../../User_File/Application/Gimbal/Gimbal.cpp)。

| 顺序 | 函数 | 作用 |
| --- | --- | --- |
| 1 | `INS_State_Topic.ReadFresh(ins, 10000U)` | 检查 INS 年龄不超过 10 ms |
| 2 | `Gimbal_Command_Topic.ReadWithMeta()` | 读目标、模式和 sequence |
| 3 | 两轴 `GetFeedbackSnapshot()` | 读同一设备内部一致快照 |
| 4 | `SetEnabled(enabled)` → 两轴 `RequestEnabled(enabled)` | enabled = initialized 且非 DISABLED 且 INS 有效；不先等 ready |
| 5 | `UpdateTarget(message)` | 根据模式、ready 边沿和 sequence 更新目标 |
| 6 | `Control(pitch_snapshot)` | 计算 Yaw/Pitch 输出并提交设备接口 |
| 7 | `PublishFeedback()` | 每 10 次调用发布一次 GimbalFeedback，所有分支共用分频 |

未获许可时跳过 UpdateTarget/Control，清除应用 ready 历史，并请求已注册电机失能。初始化部分失败仍可安全请求已成功注册的那一轴失能。已有控制任务未处理 Gimbal_Init 返回值，应用自身的 initialized 阻止正常控制。

### 目标与恢复

- 未 ready、首次/恢复 ready、进入 LOCK：`CapturePose(sequence)` → `ResetControllers()`，记录当前 INS 姿态、清速度前馈、记录当前命令序号。
- 已持续 ready 的 IMU 模式且出现新序号：装载命令中的两轴角度和速度前馈。
- LOCK 保持捕获姿态，忽略命令目标字段。
- IMU 恢复当周期先捕获，旧目标不重放；之后需要新发布序号。同值目标若 RobotCmd 不重新发布，恢复后不会自动继续追踪旧目标。
- 快照在 RequestEnabled 之前读取，本周期请求变化可能下一周期才反映在应用 ready 判断。

### Yaw：应用内串级闭环

```text
e = remainder(target_yaw - ins.yaw, 2π)
→ yaw_angle_pid.Set_Target(e), Set_Now(0)
→ TIM_Calculate_PeriodElapsedCallback()
→ yaw_angle_pid.Get_Out() + target_yaw_speed
→ 限制到 yaw_speed_limit
→ yaw_speed_pid.Set_Target(speed)
→ yaw_speed_pid.Set_Now(Gyro(配置轴, 配置符号))
→ TIM_Calculate_PeriodElapsedCallback()
→ Get_Out() 并按 yaw_torque_limit 限幅
→ yaw_motor.SetTorque(torque)
```

角度环输出 rad/s；速度环输出 N·m。现在 Yaw 速度 PID 默认 Kp/Ki/Kd 全零，默认不会产生主动 Yaw 转矩。这里的 PID 回调名称是历史命名，调用发生在 ControlTask 中。

### Pitch：姿态误差换算为电机 MIT 目标

```text
p_ref = 电机位置 + ratio × (target_pitch - ins.pitch)
v_ref = 电机速度 + ratio × (target_pitch_speed - gyro_pitch)
→ 位置机械限幅、速度限幅
→ pitch_motor.SetMIT(p_ref, v_ref, pitch_kp, pitch_kd, 0)
```

Kp/Kd 发给电机内部控制器，当前 DMMotor 没有软件 PID。位置和速度都来自本周期同一次 Pitch 快照。电机编码器位置与 INS 姿态并非相同零位；反向配置只在协议边界转换一次。

配置入口：[Gimbal_Config.h](../../User_File/Application/Gimbal/Gimbal_Config.h)，硬件总线入口：[gimbal_board_config.cpp](../../User_Config/Board/gimbal_board_config.cpp)。默认云台板两轴使用 FDCAN1；Yaw 发送/反馈 ID 为 0x03/0x005，Pitch 为 0x09/0x019；这些是源码参考值，需要与实际设备一致。

## 6. 下发和反馈是两条异步链

周期目标发送：

```text
Control()
→ SetTorque() 或 SetMIT()
→ Class_DMMotor::Publish()
→ CAN_Tx_Perform()：复制到同一 (FDCAN, ID) 的最新值槽

独立 Can_Tx_Task 每 1 ms：
BSP_CAN_SendAsync()：离散 FIFO
→ BSP_CAN_SendPer()：最新周期槽
→ BSP_CAN_SendMsg()
→ HAL_FDCAN_AddMessageToTxFifoQ()
→ 总线发送 → 电机内部控制器
```

首次/状态边沿使能或失能则走 `RequestEnabled()` → `SendModeCommand()` → `CAN_Tx_Submit()` 的离散 FIFO。StatusTask 每 10 ms `DaemonManager::CheckAll()` → `Class_DMMotor::ServiceAll()`，补交失败安全目标和协议命令、执行设备掉线保护，依据在线无故障反馈纠正请求与实际状态。

**软件通道接收、HAL 接受、总线发送、设备接收、实际执行是不同阶段。** 当前 Gimbal 将正常 SetTorque/SetMIT 返回值转为 void，未维护周期槽失败状态；ready/Gimbal_GetStatus 不证明目标提交成功。新增功能若需要可观测性或重试，须明确接口返回值处理，不把 ready 当作发送确认。

电机反馈返回：

```text
FDCANx_IT0_IRQHandler()
→ HAL_FDCAN_IRQHandler()
→ HAL_FDCAN_RxFifo0Callback()
→ HAL_FDCAN_GetRxMessage()
→ 根据 (总线, 反馈 ID) 找注册入口/context
→ Class_DMMotor::FeedbackCallback(..., this)
→ 检查 8 字节、总线、ID、节点号
→ 解码状态/位置/速度/转矩/温度，Feed Daemon
→ 下一控制周期 GetFeedbackSnapshot()
```

INS 是独立测量链：BMI088 EXTI/SPI DMA 推进采集并通知 BMI088_Task → `BSP_BMI088.Calculate()` 批量处理 FIFO → `System_IMU_Publish_State()` 检查 finite → `INS_State_Topic` → Gimbal。姿态发布发生在每批解算之后，不应把传感器采样频率当作 Topic 发布频率。

GimbalFeedback 的姿态来自 INS，enabled 是应用许可和双轴 ready 汇总，按 100 Hz 发布。`RobotCmd_GetGimbalFeedback()` 是按需读取入口，接受 100 ms 内的反馈；RobotCmd_Update 不自动调用它。

## 7. 对照当前打开的 Chassis.cpp

[Chassis.cpp](../../User_File/Application/Chassis/Chassis.cpp) 与 Gimbal.cpp 同属 Application，底盘不是云台控制的中间层。

```text
ChassisBoard Control_Task
→ BoardTransport_Poll()：将收到的命令发布本地 Topic
→ Chassis_Update()
  → Chassis_Command_Topic.ReadFresh(...,100000U)
  → 八个电机 GetMotionSnapshot()
  → 两个电机组 RequestEnabled(mode != ZERO_FORCE)
  → Chassis_CalculateTargets()
      vx/vy/wz → 四轮速度向量 → atan2 舵角 → 最短转向/轮速反转
      → 行走轮 rad/s、转向电机累计角 rad
  → wheel_group.Control(四轮速度)
  → steer_group.Control(四个角度)
      → SetRef → 无参 Group::Control → 每个 DJIMotor::Control
      → 驱动中的 PID → Group::Send → CAN_Tx_Perform
  → Chassis_UpdateFeedback() → 100 Hz Publish
```

注意 DJI 重载差异：`Group::Control(ref1,...,ref4)` 会计算并发送；无参 `Group::Control()` 只逐个计算；单独 `DJIMotor::Control()` 不完成组报文提交。[实现](../../User_File/Device/Peripheral/Motor/DJImotor/dji_motor.cpp)。

Chassis 的轮速/舵角闭环由 DJI 驱动执行；Gimbal 的 Yaw PID 在应用层执行。相同的是任务→应用→设备→BSP→发送任务，不能因此把 DM 和 DJI 的控制接口互换。

双板时 RobotCmd 的底盘 Output 通过固定 Transport 发 0x141；底盘反馈通过 0x222 返回。Gimbal/INS 板内路径不经过 Transport。`FOLLOW_GIMBAL_YAW`、`ROTATE` 虽有枚举，当前 Chassis 未实现各自独立控制分支；不能仅选择枚举就得到跟随控制。

## 8. 新功能应该改哪里

| 目标 | 首选修改位置 | 必须配套核对 |
| --- | --- | --- |
| 接入遥控云台 CH3/CH4 | Input/remote_input.cpp 中整理 `remote.gimbal` | 摇杆→rad/s→按 dt 积分为姿态目标；解锁/恢复时捕获初值、Pitch 限幅、合法时间戳；保留 Remote 安全互锁 |
| 自瞄/视觉输入 | Device/BSP 解析；任务适配器调用 `InputState_SubmitVision()` | 使用 INS 坐标绝对 rad；合法性/时间戳；在既有来源选择逻辑明确允许 vision；当前目标过期转 LOCK |
| 新键鼠/VTM 来源 | 任务适配器调用 `InputState_SubmitKeyboard()` / `SubmitVtm()` | 来源由已有选择逻辑 `InputState_Select()` 切换；新来源须有切换后的新鲜命令，仍受 Remote 许可约束 |
| 平滑转向/轨迹/新的控制算法 | Gimbal 私有 Context、UpdateTarget、Control、Gimbal_Config.h | 复用现有 Algorithm；初始化状态、1 ms dt、reset/恢复、单位和限幅；保持驱动安全门控 |
| 新云台模式 | message_types.h + 仲裁校验 + Gimbal 目标/控制逻辑 | Input 来源映射、GimbalChanged 的比较字段、停机/恢复、反馈与文档；只加枚举不够 |
| 新电机或换协议 | 应用持有新 Device；新协议放 Device/Peripheral | 唯一所有者、显式 Init、反馈校验/快照、Daemon、命令与连续目标发送语义、CMake |
| 换 CAN 接线 | 所选 BoardConfig 与应用 Config | ID、模式、PMAX/VMAX/TMAX、方向、限位；驱动接口复用 BSP |
| 底盘跟随云台 | 输入/RobotCmd 组织目标，Chassis 实现明确模式算法 | 当前反馈不提供保证可用的车体相对 Yaw；先定义相对朝向来源/坐标和时效，再设计跨板契约；线上变化检查两端 |

输入回调只保存解析结果，任务上下文再提交 InputState；这些 setter 没有跨任务/ISR 并发保护。RobotCmd_SetGimbal 不是任意任务可抢占目标的通道，运行中的仲裁会覆盖缓存。连续目标用 Topic；不可覆盖的一次动作选择已有 EventQueue 语义。

### 示例：先接入“摇杆控制云台”

1. 明确 CH3/CH4 的轴、正方向、最大角速度和 Pitch 范围，确认所用板型与默认控制参数。
2. 在 RemoteInput_Update 的健康解锁分支构造 GimbalCmd。将摇杆归一化值转换为 rad/s，以实际设计的 0.001 s 周期更新目标角；角目标初值来自新鲜有效 INS 或明确捕获流程，不能默认直接指向零。
3. 将完整云台目标写入 `remote.gimbal`，保持 InputState_SubmitRemote → 仲裁 → RobotCmd 这条路径，不直接操作 ctx 内电机。
4. 保留 DISABLED/LOCK/IMU 语义与恢复捕获；明确恢复后重新发布目标的时机，避免同值没有新序号而保持捕获姿态。
5. 按当前板型验证编译与集成；需要改变板型/硬件开关时由功能任务明确选择，不能把构建所有板型当成默认验证。此说明未开启任何硬件控制开关。
6. 功能验证覆盖输入失联、INS 过期、电机未 ready/故障、LOCK 切换、IMU 新目标及恢复后同值重新发布。最后在实机核对方向、零位、量程、限幅与控制周期。
